# InvisibleWaterMark

> **사진을 위한 비가시(Invisible) 워터마크 & 암호학적 원작자 증명 도구**  
> 모든 연산은 로컬 기기 내에서만 처리되며, 원본 사진과 개인키는 절대 외부로 전송되지 않습니다.

본 프로젝트는 이미지의 **사전 도용을 물리적으로 차단하지는 못하지만, 무단 도용 발생 시 출처를 정밀하게 추적하고 암호학적으로 원작자임을 확정 증명**합니다. 기술적으로 방어할 수 없는 범위는 [알려진 한계](#알려진-한계)에서 투명하게 밝힙니다.

## English Summary (TL;DR)

**Invisible watermarking for photos, with cryptographic proof of authorship.**  
Everything runs entirely on your local machine; photos and private keys never leave your environment.

### Key Architecture: Three Layers, Three Roles
| Layer | Location | Survives | Cryptographic Role |
|---|---|---|---|
| **Author Tag** (48-bit) | DWT Level 2 (Sparse) | Recompression, crop, denoise, **overwriting** | Points to your public key |
| **Message Payload** | DWT Level 1 (Dense) | Standard social media upload/download | Optional text display |
| **Sidecar (`.sig.json`)** | Separate JSON file | Independent of image file | Ed25519 digital signature (Non-repudiation) |

### Core Design Principles
1. **Pre-scale to Target Platform**: Photos are resized to target dimensions (e.g., Instagram 1080px) before embedding, avoiding catastrophic watermark loss from platform downscaling.
2. **Key-Derived Sparse Embedding**: Each public key pseudo-randomly selects 48 out of 192 grid cells (`SHA256(seed || cell)`). When an attacker re-watermarks the image, the cells rarely collide, allowing 41–44 out of 48 bits of the original tag to survive.
3. **Perceptual Masking**: Suppresses embedding in low-variance/flat regions (e.g., skies, plain backgrounds) to prevent visible grid artifacts while preserving PSNR > 45 dB.
4. **Privacy-Preserving Face Redaction**: Irreversible solid-color redaction (median color quantization + noise jitter) drops re-identification to ~2.0% (compared to 100% on standard mosaic).
5. **Zero-Network Architecture**: Verified 0 outbound network requests. All algorithms have 100% bit-exact parity between Python and Client-Side Web (Canvas/JS).

For complete technical documentation, see the [한국어 상세 문서](#invisiblewatermark-상세-문서) below.

## 1. 핵심 아키텍처: 3중 보호 계층

워터마크 데이터는 물리적 한계와 목적에 따라 세 계층으로 분리되어 처리됩니다.

```
[ 원본 이미지 ]
   │
   ├─► DWT Level 2 (거친 골격) ──► 작성자 태그 (48-bit SHA-256 공개키 해시, 희소 격자 배치)
   │
   ├─► DWT Level 1 (미세 계수) ──► 문장 페이로드 (텍스트, CRC32 검증)
   │
   └─► 파일 외부 분리 보관   ──► 사이드카 (.sig.json, 원본/보호본/pHash 해시의 Ed25519 서명)
```

| 구분 | 작성자 태그 (Author Tag) | 문장 페이로드 (Message) | 사이드카 증명서 (`.sig.json`) |
|---|---|---|---|
| **저장 위치** | 이미지 내부 (DWT Lv.2) | 이미지 내부 (DWT Lv.1) | 외부 별도 파일 |
| **페이로드** | `SHA256(공개키)` 상위 48비트 | 사용자 지정 텍스트 | 원본/보호본 해시, pHash, 문장 서명 |
| **내구성** | 재압축, 크롭, 디노이즈, **덮어쓰기** | 일반 SNS 업로드/다운로드 경로 | 이미지 변형과 무관 |
| **법적/암호학적 효력** | 해당 공개키의 소유자임을 지칭 | 단순 텍스트 안내 (증명력 없음) | **부인 방지(Non-repudiation) 확정 증명** |

- **공개키 분산 신원**: 공개키 자체가 신원 등록소 역할을 합니다. 인스타그램 프로필이나 GitHub 등에 공개키를 기재해두면 별도의 중앙 데이터베이스 없이도 제3자가 소유권을 교차 검증할 수 있습니다.
- **사이드카 분리 이유**: 48비트 비가시 태그 공간에는 512비트 Ed25519 전자서명 전체를 실을 수 없으므로, 암호학적 최종 확증은 사이드카 파일이 담당합니다.

## 2. 빠른 시작 (Quick Start)

### 실행 방법 1: macOS (가장 쉬운 실행)
1. Finder에서 `실행.command` 파일을 더블클릭합니다.
2. 최초 실행 시 필요한 가상환경 및 패키지를 자동으로 설치합니다 (1~2분 소요, 인터넷 필요).
3. 준비가 완료되면 브라우저에서 `http://127.0.0.1:8765`가 자동으로 열립니다.
   - 이미 실행 중인 경우 중복 서버를 띄우지 않고 새 브라우저 탭만 엽니다.
   - 브라우저 창을 닫거나 10분간 유휴 상태가 지속되면 서버가 안전하게 자동 종료됩니다.

### 실행 방법 2: 터미널 수동 실행
```bash
# 가상환경 생성 및 의존성 설치
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

# 로컬 API 및 데스크톱 웹 서버 구동
python server.py
# → 브라우저에서 http://127.0.0.1:8765 접속
```

### 실행 방법 3: 웹 앱 (설치 없이 브라우저 단독 실행)
`site/` 디렉터리는 정적 웹 애플리케이션으로 구성되어 있습니다. Vercel, GitHub Pages 등에 배포하거나 로컬에서 바로 열어 사용할 수 있습니다. WebAssembly/JS 기반으로 브라우저 탭 내부에서 모든 계산이 완결되며, 서버로 사진이 전송되지 않습니다.

### 첫 실행 및 키 생성
최초 실행 시 서명에 사용할 **내 도장(키 쌍)**을 생성합니다.

1. **암호로 보호하여 생성 (권장)**: 비밀번호를 2회 입력받아 개인키를 암호화하여 저장합니다.
2. **암호 없이 생성**: 로컬 파일 시스템 권한(`0600`)만으로 보호합니다.
3. **키 없이 사용하기**: 전자서명 없이 텍스트 문장만 심는 [간단 모드](#간단-모드-키-없이-텍스트만-삽입)로 즉시 진입합니다.

> [!WARNING]
> **개인키 백업 필수**  
> 생성된 개인키는 `~/.watermark/key.pem`에 저장됩니다. 개인키를 분실하면 지금까지 배포된 사진의 워터마크가 본인의 것임을 암호학적으로 증명할 수 있는 방법이 영구히 사라집니다. 반드시 안전한 외부 저장소에 백업하십시오.

## 3. 핵심 엔지니어링 설계

### 1) 플랫폼 규격 선행 리사이즈 (Pre-scaling)
비가시 워터마크는 리사이즈(축소 알고리즘)에 가장 취약합니다. 3000px 원본에 워터마크를 심은 채 인스타그램에 업로드하면, 플랫폼 내부 리사이즈(1080px 축소) 과정에서 주파수 계수가 파괴되어 검출률이 무작위 확률 수준으로 떨어집니다.  
**본 도구는 인스타그램(1080px) 등 업로드 대상 플랫폼 규격에 맞춰 먼저 이미지를 리사이징한 후 워터마크를 삽입**합니다. 플랫폼의 추가 크기 변경이 발생하지 않으므로 워터마크가 온전히 보존됩니다.

### 2) DWT 레벨 2 저주파 대역 삽입
디노이즈, 블러, JPEG 재압축 등 대부분의 이미지 훼손 공격은 고주파 대역부터 파괴합니다. 본 시스템은 반대로 **DWT(이산 웨이블릿 변환) 레벨 2**, 즉 이미지의 구조적 형태를 이루는 거친 뼈대 영역에 신호를 실어, 신호를 지우려 할 경우 사진의 형태 자체가 파괴되도록 설계했습니다.

### 3) 키 파생 희소 격자 배치 (Sparse Grid Allocation)
QIM(양자화 지수 변조) 알고리즘 특성상 동일 위치에 새로운 신호를 덮어쓰면 기존 신호가 덮어씌워집니다.  
이를 방지하기 위해 $12 \times 16$ (총 192칸) 격자 중 **공개키 해시값에 의해 의사난수적으로 선택된 48칸에만 신호를 분산 삽입**합니다. 공격자가 임의의 다른 키로 사진을 덮어쓰더라도 두 키가 선택하는 칸은 평균 12~15칸만 겹치므로, 원작자의 신호는 41~44비트 이상 안전하게 보존됩니다.

### 4) 지각 마스킹 (Perceptual Masking)
하늘이나 단색 벽면처럼 매끈한 영역에 QIM 신호가 삽입되면 육안으로 격자형 얼룩(Artifact)이 드러납니다.  
이를 방지하기 위해 국소 AC 에너지가 양자화 간격 기준치(`MASK_K = 0.5`)에 미달하는 평탄한 블록은 삽입을 건너뜁니다 (신호 완전 소멸 방지를 위한 `MASK_FLOOR` 설정 병행).

- **화질 개선 효과**: 그라디언트 시험 이미지 기준 평탄 영역의 최대 픽셀 변화량이 $9 \to 0$으로 제거되며 격자 무늬가 완전히 사라집니다.
- **설계 트레이드오프**: 마스킹을 활성화할 경우 극한 편집(정중앙 크롭, 크롭+밝기조작)에 대한 내성이 소폭 감소하지만, 육안 식별 불가능한 원본 품질 보존을 위해 채택된 최적의 균형점입니다.

## 4. 공격 내성 및 벤치마크

### 공격 유형별 검출률 (Instagram 1080×720, 48비트 중 복원 비트)
> 지각 마스킹이 적용된 실측값입니다. 우측 PSNR은 공격당한 사진 자체의 품질을 나타냅니다.

| 공격 유형 | 복원 결과 | 공격본 사진 품질 (PSNR) | 비고 |
|---|---|---|---|
| **SNS 업로드 재압축** | **48 / 48 (100%)** | 39.0 dB | 완전 복원 |
| **강한 재압축 (JPEG q60)** | **48 / 48 (100%)** | 36.2 dB | 완전 복원 |
| **스크린샷 캡처** | **48 / 48 (100%)** | 38.4 dB | 완전 복원 |
| **다운로드 후 50% 축소** | **48 / 48 (100%)** | 38.8 dB | 완전 복원 |
| **외곽 10% 크롭 (Crop)** | **48 / 48 (100%)** | 29.5 dB | 크롭 탐색 엔진 자동 복원 |
| **정중앙 40% 크롭** | **소실 (43 / 48)** | 16.3 dB | 사진 심각 훼손 상태 |
| **노이즈 제거 (Denoise)** | **45 / 48 (93.8%)** | 37.6 dB | 원작자 식별 유효 |
| **디노이즈 + 강한 재압축** | **46 / 48 (95.8%)** | 36.9 dB | 원작자 식별 유효 |
| **12% 극단 축소 후 원복** | **47 / 48 (97.9%)** | 38.2 dB | 원작자 식별 유효 |
| **밝기 / 대비 왜곡** | **48 / 48 (100%)** | 18.2 dB | 완전 복원 |
| **크롭 + 밝기/대비 복합 왜곡** | **소실 (41 / 48)** | 15.7 dB | 사진 심각 훼손 상태 |

> [!NOTE]
> 워터마크가 소실되는 구간(정중앙 크롭, 크롭+색보정)은 사진 자체의 PSNR이 15~16 dB 수준으로 떨어져 원본으로서의 가치가 상실되는 파괴적인 변형 영역입니다. 즉, **"사진의 형태가 보존되는 한 워터마크는 유지된다"**는 신뢰성을 보장합니다.

### 덮어쓰기 공격(Re-watermarking) 생존력
원작자가 보호한 이미지를 제3자가 가져가 자신의 키로 다시 워터마크를 심었을 때의 검출 결과입니다.

| 상태 | 원작자 태그 | 도용자 태그 | 검출되는 문장 |
|---|---|---|---|
| 원작자 보호 직후 | **48 / 48** | — | 원작자 텍스트 |
| **도용자가 그 위에 재삽입** | **41 ~ 44 / 48 검출** | 48 / 48 | 도용자 텍스트 |

- 원작자의 48비트 태그 중 **41~44비트가 온전히 살아남아 두 태그가 공존**합니다.
- 무작위 48비트 중 43비트가 우연히 일치할 확률은 약 **7,300만분의 1($1.37 \times 10^{-8}$)**로 암호학적 입증력이 충분합니다.

### 화질 측정 결과 (Image Quality)
| 삽입 구성 | PSNR | SSIM |
|---|---|---|
| 작성자 태그 단독 | **47.2 dB** | 0.998 |
| 태그 + 문장 페이로드 | **45.9 dB** | 0.985 |
| 키 없이 문장만 삽입 | **49.2 dB** | 0.998 |

지각 마스킹 활성화 시 매끈한 영역의 픽셀 변화 평균과 최댓값이 모두 0으로 억제되어 육안상 원본과 구별되지 않습니다.

## 5. 다단계 복원 탐색 알고리즘

공격에 의해 변형된 사진을 복원하기 위해 연산 비용이 낮은 단계부터 순차적으로 탐색을 확장합니다.

```
[입력 이미지]
   │
   ├─► [1단계] 직접 검출 (후보 2개, 0.0초) ──► 39/48 일치 시 즉시 성공
   │
   ├─► [2단계] 밝기·대비 역추정 (후보 80개, ~0.1초) ──► 41/48 일치 시 즉시 성공
   │
   └─► [3단계] 2D 크롭 벡터 정렬 전수 탐색 (후보 200만개, ~0.9초) ──► 46/48 일치 시 성공
              └─► 타임아웃 예산 (최대 12초 초과 시 탐색 중단)
```

1. **1단계 (직접 검출)**: 입력본 및 원본 해상도 역스케일본을 직접 분석 (후보 2개, 요구 일치: 39/48).
2. **2단계 (밝기/대비 보정)**: 게인(Gain)과 오프셋(Offset) 후보 40조합을 적용 (후보 80개, 요구 일치: 41/48).
3. **3단계 (크롭 정렬 전수 탐색)**: 픽셀 오프셋 및 192개 격자 시프트를 전수 탐색 (후보 약 200만 개, 요구 일치: 46/48).
   - **벡터화 최적화**: 픽셀 4칸 차이는 DWT 계수 이동과 수학적으로 동일하므로, DWT를 4회만 사전 계산한 뒤 슬라이싱으로 계수를 재사용하여 탐색 시간을 수 분에서 **0.9초**로 단축했습니다.
   - **오탐 확률 제어**: 탐색 후보 수가 늘어남에 따라 통계적 오탐율을 $10^{-4}$ 이하로 억제하도록 단계별 필요 일치 비트를 엄격히 차등 적용합니다.
   - **12초 제한 예산**: 워터마크가 없는 일반 사진 처리 시 무한 루프에 빠지지 않도록 2·3단계 총합 최대 12초의 Wall-clock 예산을 적용합니다.

## 6. 덮어쓰기 공격(Ambiguity Attack) 방어

원작자의 작업물에 자신의 워터마크를 덮어씌워 소유권을 주장하는 공격(Ambiguity Attack)을 3단계로 원천 무력화합니다.

```
[도용자 주장] "내가 원작자다" ──► 도용자가 서명한 원본 해시: e76627e1...
                                        ▲ 동일
[원작자 증명] "아니다, 내 보호본이다" ──► 원작자가 서명한 보호본 해시: e76627e1...
             "진짜 원본은 이것이다" ──► 원작자만 가진 원본 해시: 804f1110... (도용자 생성 불가)
```

1. **물리적 신호 생존**: 키 기반 희소 배치를 통해 도용자가 덮어쓰더라도 원작자 태그 41~44비트가 보존됩니다.
2. **지각 해시(pHash) 파생 증명**: 63비트 시각적 구조 해시를 사이드카에 함께 서명하여 동일한 원본에서 파생된 이미지임을 입증합니다 (동일/편집본: 해밍 거리 2~16, 무관한 사진: 22~40).
3. **사이드카 원본 확정 증명**:
   - 도용자가 서명에 사용하는 파일 해시는 원작자의 **"워터마크 처리된 출력본"**의 해시입니다.
   - 원작자는 워터마크가 적용되기 이전의 **"진짜 원본 파일"**과 그에 대한 디지털 서명을 보유하고 있습니다. 도용자는 수학적으로 이 원본 해시를 역산하거나 위조할 수 없습니다.

> [!TIP]
> 사진 보호 완료 시 브라우저에서 안내하는 **3대 요소(보호된 이미지, 사이드카 `.sig.json`, 원본 파일)**를 반드시 함께 보관하십시오.

## 7. 부가 기능 (프라이버시 & 메타데이터)

### 1) 초상권 보호 얼굴 가리기 (Face Redaction)
사진에 포함된 타인의 초상권을 영구히 보호하기 위해, 워터마크 및 해시 계산 직전에 얼굴 영역을 비가역적으로 제거합니다.

```
[사진 입력] ──► 3종 앙상블 자동 탐지 ──► 사용자 수동 보정 (브러시/박스) ──► 단색 비가역 마스킹
```

- **단색 마스킹 (기본 권장)**: 해당 영역의 채널별 중앙값을 16단계로 양자화하여 채운 뒤 미세 노이즈를 추가합니다. 잔여 정보량이 3개 값으로 축소되어 수학적으로 원본 복원이 원천 불가능합니다.
- **모자이크 마스킹 (비권장)**: 모자이크의 블록 평균값에는 원본 정보가 다량 잔존하여 딥러닝 기반 복원 공격에 취약합니다.

#### 재식별 공격 실험 결과 (200장 후보군 중 원본 매칭률, 무작위 확률 0.5%)
| 가리기 방식 | Top-1 재식별률 | 남는 정보량 |
|---|---|---|
| **단색 마스킹 (권장)** | **2.0%** (식별 불가 수준) | 3개 양자화 값 |
| **모자이크 (기본값: 블록4 / 지터12)** | **100.0% (완전 식별)** | 48개 샘플 |
| 모자이크 (블록2 / 지터96) | 1.0% | 12개 샘플 (형태 완전 뭉개짐) |

- **3종 앙상블 얼굴 탐지기**: TinyFaceDetector(2개 입력 크기) + SSD MobileNet v1을 결합하여 고난도 테스트셋(정답 24명) 기준 22명을 탐지합니다. 미탐으로 인한 프라이버시 침해를 막기 위해 수동 박스 추가/삭제 기능을 제공합니다.

### 2) 메타데이터(EXIF) 완전 삭제 모드
워터마크 삽입 없이 **GPS 좌표, 촬영 시각, 카메라 기종 정보만 제거**할 수 있습니다. 픽셀을 직접 디코딩하여 새 캔버스에 렌더링 후 재인코딩하는 방식을 사용하여 잔여 메타데이터를 100% 소거하며, 회전(Orientation) 정보를 픽셀에 미리 반영하여 사진 회전 오류를 방지합니다.

### 3) AI 학습 거부 표준 선언 (IPTC/PLUS)
생성형 AI 크롤러의 무단 스크래핑을 거부하기 위해 국제 표준 메타데이터 규격을 JPEG XMP(APP1) 세그먼트에 명시합니다.
```xml
plus:DataMining = "http://ns.useplus.org/ldf/vocab/DMI-PROHIBITED-AIMLTRAINING"
```
- IPTC Photo Metadata 2023.1 및 PLUS 표준 준수.
- 사이드카 서명에 해당 선언문이 포함되므로 사후 법적 분쟁 시 고의적 침해 입증 자료로 활용 가능합니다.
- *참고: SNS 업로드 시 메타데이터는 제거되므로, 원본 파일이 직접 유통되는 포트폴리오 사이트나 이메일 전달 경로에서 유효합니다.*

### 4) 간단 모드 (키 없이 텍스트만 삽입)
전자서명 및 암호학적 입증 절차 없이 안내 문구만 가볍게 남기고 싶은 경우 사용합니다.
- 사이드카(`.sig.json`)를 생성하지 않으며 화질 저하가 가장 적습니다 (PSNR 49.2 dB).
- 타인의 악의적 도용에 대한 법적·수학적 소유권 입증력은 제공되지 않습니다.

## 8. 로컬 프라이버시 및 보안 검증

사용자의 개인키와 사진이 단 1바이트도 외부로 유출되지 않음을 보증하기 위해 철저한 보안 통제를 적용했습니다.

| 검증 항목 | 검증 방식 | 검증 결과 |
|---|---|---|
| 소스 코드 외부 송신 검사 | `requests`, `urllib`, `socket` 등 외부 호출 전수 검사 | **외부 호출 0건** |
| 프론트엔드 통신 주소 | 브라우저 `fetch` 네트워크 트래픽 분석 | `/api/*` 로컬 상대경로만 존재 |
| 외부 웹 폰트 / CDN 의존 | 외부 리소스 URL 전수 검사 | 의존성 전무 (`data:`, `blob:`만 사용) |
| 실시간 패킷 감시 | 사진 처리 중 `lsof` / 소켓 상태 추적 | **루프백(127.0.0.1) 외 연결 0건** |
| 로컬 디스크 파일 잔재 | 대용량 업로드 처리 중 임시 디렉터리 모니터링 | 디스크 기록 없이 **순수 메모리에서만 처리** |

### 로컬 엔지니어링 보안 조치
1. **인메모리 스풀 강제**: Starlette 기본 임계값(1MB)으로 인해 대용량 사진이 시스템 임시 폴더에 쓰이던 문제를 스풀 상한 조정을 통해 완전히 차단했습니다.
2. **Host / Origin 검증**: 악성 웹사이트가 브라우저를 매개로 로컬 API(`127.0.0.1:8765`)에 위조 요청(CSRF/DNS Rebinding)을 보내 개인키 서명을 탈취하지 못하도록 엄격한 헤더 검증을 수행합니다.
3. **유휴 자동 종료**: 브라우저 탭이 닫히거나 사용자 조작이 10분간 없을 경우 로컬 서버가 자동으로 프로세스를 종료합니다.

## 9. 웹 앱 및 데스크톱 호환성

Python(데스크톱) 엔진과 JavaScript(웹 브라우저) 엔진은 수학적으로 완전히 동일하게 설계되었습니다. 웹에서 보호한 이미지를 데스크톱에서 검증하거나, 그 반대의 작업이 100% 호환됩니다.

| 연산 항목 | 검증 오차 및 일치율 |
|---|---|
| 4×4 DCT 변환 행렬 및 Haar DWT 2단계 | 절대 오차 $\le 10^{-13}$ |
| SVD (최대 특이삼중항) 계산 | 절대 오차 $\le 3 \times 10^{-13}$ |
| 작성자 태그 및 격자 좌표 선정 | **완전 일치 (Bit-exact)** |
| 태그 삽입 후 픽셀 결과 | 98,304개 픽셀 전체 동일 |
| CRC32 검증 및 문장 프레임 디코딩 | **완전 일치** |
| 지각 해시 (pHash) | 동일 파일 기준 완전 일치 |
| **상호 검증 (Cross-verification)** | **웹 생성본 ↔ 파이썬 검출기 48/48 비트 완벽 검증** |

## 10. 알려진 한계

과장 없는 명확한 보안 모델을 위해 기술적으로 해결할 수 없는 제약 사항을 명시합니다.

1. **생성형 AI 재생성(img2img) 방어 불가**: 확산 모델(Diffusion Model) 등을 거쳐 이미지를 새로 합성할 경우 기존 주파수 신호는 완전히 소멸됩니다 (현재 모든 비가시 워터마크 기술의 공통 한계).
2. **사전 다운로드 방지 불가**: 공개된 웹에 올린 사진을 타인이 저장하는 행위 자체는 막을 수 없으며, 사후 추적 및 소유권 증명에 집중합니다.
3. **표적 덮어쓰기 공격**: 공격자가 원작자의 공개키를 파악하고 소스 코드를 수정하여 정확히 해당 48개 격자만 타겟팅해 변조할 경우 방어가 어렵습니다.
4. **극소 크롭 한계**: $12 \times 16$ 격자 및 블록 단위를 유지해야 하므로 최소 $256 \times 192\text{px}$ 이상의 영역이 보존되어야 검출할 수 있습니다.
5. **크롭 후 임의 리사이즈 복합 공격**: 정렬 오프셋은 탐색할 수 있으나 미지의 축소 비율까지 동시에 탐색하는 것은 수학적으로 불가능합니다.
6. **타임스탬프 공증 미제공**: 서명에 기록되는 일시는 시스템 시간 기준입니다. 블록체인 등 외부 공증 서버를 사용하면 사진 해시가 유출되므로 '100% 로컬 환경' 유지를 위해 외부 타임스탬프 연동은 의도적으로 제외되었습니다.
